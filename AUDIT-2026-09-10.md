## Security Findings

No hardcoded secrets are tracked (independently confirmed: `git ls-files` contains no `.env*`, and the only environment read in the codebase is the opt-in `AUTOMONKEYTYPE_RUN_LIVE` flag at `tests/test_live_smoke.py:12`). The attack surface is a single-user local CLI with no network service, no database, no deserialization of external data, and no LLM/tool-calling path.

## Deslop Applied

Commit `refactor(deslop)`. All three changes are behavior-preserving; production diffs are 3 hunks across 2 files.

- **`automonkeytype/scraper.py:24` — removed dead `SEL_CARET = "#caret"`.** Defined but referenced nowhere in the repository (`grep -rn SEL_CARET` → 0 hits in `automonkeytype/`, `tests/`, and the fixture after removal). It is a pure data constant with no reader, so deleting it cannot alter behavior.
- **`automonkeytype/scraper.py:120-145` — deduplicated word-text extraction.** `get_all_words()` and `get_active_word()` each inlined the identical pair of operations `word_el.query_selector_all(self.SEL_LETTER)` and `"".join(letter.text_content() or "" for letter in letters)`. Extracted into `_word_text(word_el)`; both call sites now use it. Same selector, same element order, same join expression → byte-identical output. `get_all_words()` additionally hoists its single-use `word_elements` local into the `for` header.
- **`automonkeytype/humanizer.py:135` — `elif` → `if` after a `return`.** The `elif` was unreachable as a branch selector (the preceding branch always returns), so both spellings take exactly the same path for `,`/`;`/`:` input and for all other input.
- **Deliberately NOT changed:**
  - The three `except Exception: pass` sites — triaged above as intentional; rewriting them (`contextlib.suppress`) is a style conversion, not slop removal.
  - `TypingHumanizer.reset()` and `WPMController.reset()` — never called by production code, but they are public API with direct unit tests; removing them would delete coverage. Reported instead (Full Review #7).
  - `MonkeyTypeScraper.get_active_word()` — documented as a test-only helper, but it is public API used by `tests/test_integration.py:42`. Reported instead (#6).
  - Ruff/import-sort/magic-value/`RUF012` hits and the empty `[tool.uv]` table — style rules, not slop; mass-applying them is excluded by the task. `ruff check --select F` (undefined names, unused imports/vars) passes clean, confirming there is no other unreferenced code.
  - No commented-out code blocks, no `TODO`/`FIXME`/`HACK`, and no stray `print`/`console.log` debugging exist in library code — grep-verified. The `print` call at `scraper.py:112` is a deliberate user-facing warning, not debug output.

## Full Review Findings

Ranked by impact. Read-only — no code was changed for any item below.

1. **HIGH (correctness) — `time`/`quote` modes cannot complete.** `engine.py:87-141` extracts the word list once (`_prepare_test`, `engine.py:81`) and types only that list. MonkeyType's `time` and `quote` modes stream/replace words, so the loop runs out of words long before the timer expires, and `_report_results` (`engine.py:154-172`) falls into the "Test may still be running" branch. `README.md:63,85` and `cli.py:30` advertise these modes. Fix direction: for streaming modes, re-read the active word from the DOM (`scraper.get_active_word`, already implemented) or re-extract between words until `is_test_complete()`.
2. **MEDIUM (robustness) — silent 30 s stalls in `dismiss_popups()`.** `scraper.py:79-87` loops 8 selectors with no timeout argument. Playwright's default actionability timeout is 30 s, so a visible-but-unclickable overlay (e.g. an element that never stabilizes) blocks ~30 s and then fails silently. Fix direction: pass an explicit short `timeout=` to `click()` and surface the failure.
3. **MEDIUM (dependency hygiene) — no dev/test dependency group.** `pyproject.toml` declares only `playwright` and `click`; `[tool.uv]` is empty. Reproduced: `uv run pytest` fails with `ModuleNotFoundError: No module named 'playwright'` (pytest is resolved from the system interpreter, which cannot import the project venv's Playwright), while `uv run --with pytest pytest` passes. CI papers over this with `python -m pip install -e . pytest` (`.github/workflows/tests.yml:33`). Fix direction: add `[dependency-groups] dev = ["pytest>=8"]` so the documented runner (`uv run pytest -q`) works out of the box.
4. **MEDIUM (input validation)** — see Security Findings, `--wpm 0` → `ZeroDivisionError`; `--count` is also an unvalidated free-text `str` (`cli.py:33`) that is interpolated into a CSS attribute selector (`scraper.py:53-55`); because `configure_test` only *warns* on a non-match it degrades quietly rather than failing.
5. **MEDIUM (doc drift)** — (a) `README.md:63,85` states modes are "words, time, or quote" while `cli.py:30` offers `words|time|quote|zen|custom` and `scraper.VALUE_BTN_TEMPLATES` only maps `words`/`time`; (b) `CLAUDE.md` and `README.md` still document `pip install -e .` after the uv migration (`937a30c`/`3b4b3cb`); (c) `CLAUDE.md` commands predate the `uv` workflow.
6. **LOW (maintainability) — test-only production surface.** `MonkeyTypeScraper.get_active_word` (`scraper.py:132`) is unused by the engine but public API with a docstring stating it is test-only; keep or inline it deliberately, but it is dead weight in the shipped module.
7. **LOW (maintainability) — unused lifecycle API.** `TypingHumanizer.reset()` (`humanizer.py:139`) and `WPMController.reset()` (`controller.py:96`) are never invoked outside tests; they imply a multi-test session loop that the engine does not implement (the engine builds fresh objects per run, `engine.py:35-37`).
8. **LOW (consistency) — two output helpers.** `engine._print` (`engine.py:182-184`) exists to prefix output, but `scraper.py:112-115` hardcodes the same `[automonkeytype]` prefix in a raw `print`. Two spellings of one concept; a shared output helper would remove the drift.
9. **LOW (correctness of user-facing text)** — `cli.py:26` escapes the percent sign twice inside a Click help literal (`0.05 = ~5%% errors`). Verified with `python -m automonkeytype --help`: the rendered text is literally `0.05 = ~5%% errors`. Click does not interpolate the help string, so one `%` is correct.
10. **LOW (browser robustness)** — `browser.py:91` hardcodes `wait_until="networkidle"`, which Playwright discourages (it depends on network quiescence and can hang on polling sites), plus a fixed `timeout=30000` and a caller-visible `time.sleep(2)` (`engine.py:66`). `domcontentloaded` + an explicit element wait (`scraper.wait_for_test_ready`) would be more deterministic.
11. **LOW (test coverage)** — no unit coverage for `scraper.configure_test`'s value-button mapping and warning path, `engine._nearby_key` / `_inject_error` / `_report_results`, `browser.BrowserManager.close()` idempotence, or CLI invalid input. `browser.py` stealth setup is only exercised indirectly by the integration tests, and the live smoke test is opt-in (`AUTOMONKEYTYPE_RUN_LIVE=1`).
12. **LOW (stealth quality)** — `browser.py:26-31` spoofs `navigator.plugins` as a plain `[1,2,3,4,5]` array rather than a `PluginArray`, and `languages` is hardcoded to `en-US` while `locale` is also pinned; these mismatches are themselves fingerprintable. Cosmetic relative to the tool's purpose.

## Remaining Risks

- **`time`/`quote` mode is functionally broken end-to-end** (Full Review #1). Not verified against live monkeytype.com: the live smoke test (`tests/test_live_smoke.py`) is opt-in and was skipped, so no assertion covers a 60-second timed run. This is the largest unverified behavior in the repo.
- **The stealth configuration was not validated against monkeytype.com's current detection.** `--disable-features=IsolateOrigins,site-per-process` (`browser.py:69`) still weakens site isolation; it was left in place because removing it is a behavior/design decision, and I could not measure whether detection is affected without a live run.
- **No dependency vulnerability scan was performed** (no `pip-audit`/`uv audit` executed, network-sensitive). `playwright>=1.40` and `click>=8.0` are lower-bound-only pins and `uv.lock` pins exact versions; a future `uv lock --upgrade` could pull unreviewed minors.
- **Fixes were deliberately not made** for the LOW input-validation, installer-pinning, `.env`-ignore, and CLI-help-escape items; each is documented above with a recommended fix and the reason it was deferred (behavior change / product decision / speculative config).
- **Test coverage remains 39 tests over ~1.7 kLOC**, with `browser.py` and `engine.py` (the two riskiest modules) covered only indirectly through the local fixture. No coverage measurement was run.
- **`docs/`-style artifacts are git-ignored** (`progress.md`, `findings.md`, `task_plan.md`, `docs/plans/`), so no progress file exists for this repo; this audit file is the only new artifact.
- Nothing was blocked. No pushes, force-pushes, rebases, resets, or amends were performed; all other repositories were untouched.
